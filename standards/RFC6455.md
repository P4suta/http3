# RFC 6455 conformance boundary

The reviewed source is the RFC Editor text for RFC 6455, SHA-256 `765775326aee0ecca9b04bde3fd1f52932d498e33e34e428bd61b8a24da0fa3b`,
and the RFC Editor errata inventory reviewed on 2026-09-12.
RFC 6455 is updated by RFC 7936, RFC 8307, and RFC 8441.
The HTTP/2 and HTTP/3 bootstrap mappings are assessed in their own requirement objects; RFC 6455 still owns the common subprotocol and frame rules they retain.

## Public capability

`http/websocket` is a protocol-neutral handshake and framing state machine.
It constructs and validates an HTTP/1.1 Upgrade mapping and the common parts of HTTP/2 and HTTP/3 Extended CONNECT, but it neither resolves a `ws`/`wss` URI nor owns a TCP connection, a proxy, browser origin policy, automatic reconnection, or WebSocket extensions.
Those clauses are explicitly marked `NotApplicable`, rather than being inferred from a helper that cannot observe the required state.

`http3/websocket` is the integrated RFC 9220 transport adapter.
It performs an authenticated HTTP/3 Extended CONNECT, moves RFC 6455 frames over one QUIC request stream, applies one absolute receive deadline, cancels failed streams,
and releases buffered and fragmented peer input at terminal states.
It does not make the TCP closing-order clauses applicable to QUIC.

Both frame implementations use these rules:

- clients use a fresh four-byte mask from `crypto:strong_rand_bytes/1` for every encoded frame and servers never mask;
- receivers reject the wrong masking direction, non-zero reserved bits,
  reserved opcodes, non-minimal lengths, a set 64-bit sign bit, fragmented controls, and controls larger than 125 bytes;
- fragmented messages remain ordered and cannot interleave, while Ping and Close are handled between fragments;
- complete text and Close reasons are validated as UTF-8;
- message and retained-wire limits are finite, and a received Close releases the partial message and unread wire suffix;
- extensions are default-deny, so no extension bit, opcode, parameter, or payload data is accepted without a future explicit implementation.

The HTTP/1.1 handshake combines repeated list-valued `Connection`, `Upgrade`,
and request `Sec-WebSocket-Protocol` fields.
Singleton key, accept, response subprotocol, and request version fields remain strict.
A key is accepted only when it is the canonical RFC 4648 Base64 encoding of exactly 16 bytes; this incorporates verified erratum 3150.

All reachable mandatory and advisory behavior in the advertised profile is implemented without a documented deviation.
Invalid integrated server handshakes send an empty 400 response (including version 13 for an unsupported version), await its send completion, and cancel the unread request direction.
Established protocol failures emit one finite typed qlog code without peer payload, send Close 1002, 1007, or 1009 plus FIN, await the bounded send completion, and only then cancel the receive direction.
The original typed failure remains the public result even when best-effort Close or cleanup also fails.
A STOP_SENDING/Close race has an explicit wire barrier: response-owned resources converge immediately while the independently valid Close and End events remain deliverable exactly once under a one-entry application queue.

## Errata review

| IDs | RFC Editor status | Assessment |
| --- | --- | --- |
| 3150, 3433, 3473 | Verified | 3150 changes the canonical nonce vector and has a regression. 3433 permits repeated extension response fields, outside the default-deny extension profile. 3473 clarifies connection serialization per IP-address/port, outside this transport-neutral API. |
| 4672, 4919, 6997, 7262, 7608, 5288 | Reported | 4672's continuation-frame clarification matches the implemented state machine. The others do not change reachable behavior in the advertised profile. |
| 3227, 3432, 4398, 5498 | Held for Document Update | 3227's endpoint-neutral 1011 meaning and 5498's lowercase registration agree with the implementation. 3432 is an example label correction. 4398 concerns browser mixed-content policy. |
| 3215, 3912, 4184, 5453, 8491 | Rejected | Reviewed and not applied. |

The deterministic regressions first fail against the prior behavior for the non-canonical nonce, split list fields, unacknowledged protocol-failure Close,
untyped diagnostics, invalid-handshake transport leakage, and retained terminal input.
The same named tests then pass against the current implementation.
Mutation runs independently reverse byte-pressure error classification and terminal-ceiling precedence, and both are detected.
The broader pure state-machine suite and HTTP/3 EUnit handshake/transport suites cover both endpoint roles and real authenticated transport.
Requirements audit evidence is generated independently under OTP 28 and OTP 29.
