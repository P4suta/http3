# Brotli requirement review

Reviewed on 2026-09-11 against the RFC Editor text and errata inventory.
The source hashes, individual dispositions, functions, and executable cases are recorded in `requirements.json`.
The baseline remains 2026-08-30; the review date records the actual later review.

The review uses [RFC 7932](https://www.rfc-editor.org/rfc/rfc7932.html),
[RFC 9841](https://www.rfc-editor.org/rfc/rfc9841.html), and [RFC 9842](https://www.rfc-editor.org/rfc/rfc9842.html).
RFC 7932 and RFC 9841 express obligations in lowercase prose without a BCP 14 keyword convention.
The auditor explicitly allows those two documents and rejects attempts to qualify either with an empty uppercase-only inventory.

| Document | Implemented scope | Explicit capability boundary |
| --- | --- | --- |
| RFC 7932 | Stored, metadata, and compressed meta-blocks; canonical Huffman trees; block switching and complete declared type use; literal contexts and complete map indices; distance history; all standard static dictionary transforms; bounded decoding and measured incremental history allocation | None in the complete-stream codec requirement map; explicit input, output, ratio, work, and window budgets still apply |
| RFC 9841 | The unframed raw LZ77 prefix subset used by DCB; standard static dictionary fallback; extended distance alphabet validation; extended headers within the DCB window cap | General serialized/custom dictionaries, windows above the DCB cap, and the framing container are not exposed or accepted by `DictionaryBrotli` |
| RFC 9842 | Header field parsers and serializers, dictionary hash validation, DCB/DCZ framing, a finite HTTPS-origin/freshness/destination store, the source-bound URLPattern consumer, raw-prefix decoding, and independently exercised codec windows | The integrated HTTP endpoints do not advertise, negotiate, serve, or automatically decode CDT; browser readability and cookie-coupled dictionary state are absent |

The RFC 7932, RFC 9841, and RFC 9842 maps are complete.
An implementation function and a similarly named test are insufficient to close a row:
`Implemented` rows identify an assertion or independent decoded output that exercises the actual condition.
`NotApplicable` rows identify a precise unreachable format or protocol state.
RFC 9841 completion maps the raw-prefix DCB profile without claiming a general shared-Brotli container API.

`test/brotli_contract_test.gleam` is the ordinary EUnit generator entrypoint for `test/http_brotli_test.erl`.
Its cases include 45 independent Google synthetic vectors, all 121 standard dictionary transforms, malformed Huffman trees and distances, 5,000 seeded malformed streams, every single-bit mutation of an independent compressed fixture, all standard window headers, and exact output/ratio/work limits.
Additional specification-derived fields check metadata padding, both nonminimal meta-block length forms, cumulative output over two stored blocks, and nonempty final-block padding.
A DCB stream that advertises WBITS 25 is `InvalidEncoding` even when the caller permits a larger window; a valid WBITS 24 stream rejected by a smaller caller ceiling remains `LimitExceeded`.

Ten further ordinarily discovered cases close the RFC 7932 validation and allocation gaps.
Literal, command, and distance categories each reject an adjacent repeated type and undeclared use ranges, while accepting all 256 types.
Completion checks cover final literals and final copies.
Literal and distance context maps reject missing maximum and middle indices after RLE and inverse MTF, and accept the full 256-tree boundary.
These fixtures encode RFC fields independently of the decoder; expected output follows from a literal `x` and distance-one copies.
Removing the adjacent check, retaining only a maximum-type check, retaining only a maximum-context check, or skipping copy-end validation each makes a regression fail.

History tests use an isolated OTP trace session with `call_memory`, confined to one owned worker.
Counters observe actual heap allocations and calls to the array chunk allocator; no call arguments, return values, or trace payloads are emitted.
A 1 MiB worker heap bound includes referenced binaries, and every worker is joined.
With WBITS 24, the first byte allocates no complete chunk;
1023, 1024, 1025, and 4096 output bytes allocate 0, 1, 1, and 4 chunks.
Four stored meta-blocks retain four chunks in the same history.
An eager 16 MiB window-allocation mutation fails the worker resource bound.
These observations establish allocation behavior of the bounded complete-stream decoder, rather than a whole-VM peak-memory or streaming-API guarantee.

`test/dictionary_window_test.gleam` ordinarily discovers 17 additional native contracts.
The retained fixtures in `test/fixtures/codec-window/` are generated by `scripts/codec_window_reference.py` using hash-pinned Brotli 1.1.0 and Zstandard 1.5.5 libraries, with the upstream encoder and decoder verifying the same deterministic bytes independently of this project.
The synthetic input and forced-sequence recipes are original test material; no upstream codec implementation is copied.
The script checks library bytes both before and after generation.
Reproduce with Python's standard library in the existing Linux reference image, using `--check` to compare retained bytes or `--write` to regenerate them.
Its offline container is limited to two CPUs and 2 GiB of memory; normal package tests do not require the reference tools.

The Brotli vector uses WBITS 24 and produces more than 16 MiB.
A trace scoped to its owned decoder observes copies at the maximum backward distance of 16 MiB minus 16 bytes, totaling the final 128 bytes.
Only integer distance and length records are emitted; call arguments and output bytes never enter the trace mailbox.
Five Zstandard vectors force offsets of 8, 16, 32, 64,
and 128 MiB from the output back to the first raw-dictionary bytes.
Dictionaries contain `floor(4 * window / 5) + 1` bytes, so output is about one fifth of the window.
Altering only the first dictionary bytes changes the independent decoder's result; omitting the dictionary fails.
Public DCZ decoding must produce the independent hash, while a smaller native window must reject the same stream.
The 128 MiB vector exercises the required decoder cap: it is not evidence that an encoder may emit a window equal to the Section 5 limit.

Separate public encoder tests inspect actual emitted frame windows at the dictionary-dependent floor transition and cap.
They require the window to be strictly below the RFC limit, including with input longer than 8 MiB.
The public compressor has a fixed level; private FFI levels are not a public configuration contract.
Five isolated mutations are detected: narrowing Brotli to WBITS 23, narrowing Zstandard to 64 MiB, ignoring a caller window,
removing native context close, and forcing an excessive encoder window.

Every window case uses a worker with a 256 MiB BEAM heap limit including referenced binaries, a 120-second operation deadline, and an owner monitor that joins the worker.
Native Zstandard contexts have an independently bounded window of at most 128 MiB; the heap bound is not a claim about native codec allocations or total VM memory.
Scalar traces count actual context open/close calls after success and output, work, and window refusal.
A separate synchronization test kills the owner only after a real context is open and verifies both worker and guardian DOWN.
Applications must provide dictionary and output budgets adequate for their resource before advertising support; these codec capability tests do not satisfy the conditional HTTP negotiation duties outside the current endpoint capability or expand the RFC 9841 raw-prefix subset.

The observer preserves unrelated owner-mailbox messages.
An injected message first reproduced the failure seen only in the full HTTP suite; selective matching now rejects malformed trace envelopes only from the owned worker.

`test/dictionary_store_contract_test.gleam` adds six ordinary cases for exact freshness expiry, empty destinations, trailing wildcards, all three selection precedence rules, unknown types and missing match fields, and separate top-level-site/profile keys.
These tests exposed and fixed both an inclusive expiry comparison and a trailing wildcard that incorrectly required an empty path suffix.
They do not establish complete URLPattern behavior or an HTTP negotiation policy.

The private URLPattern implementation covers the string constructor and all eight URL components.
It follows the RFC's [WHATWG snapshot](https://urlpattern.spec.whatwg.org/commit-snapshots/696b4029d52e5854044bac6b72cdb198cb962ed0/) with the explicitly reviewed [June 2026 callback corrections](https://urlpattern.spec.whatwg.org/commit-snapshots/aeb2019cf3aa1fb31af134a682c0255302a41297/).
Named segments, fixed groups, optional/repeated parts, escapes, duplicate names,
and canonical wildcard groups compile to a Thompson automaton; caller-supplied regular expressions are rejected.
Adjacent fixed groups merge before canonicalization.
Variable parts retain their boundaries, so a dot segment cannot remove a variable part.
Matching consumes already canonical URL fields;
an IPv6 pattern against a domain is an ordinary non-match.

`insert_dictionary_from_url` validates the pattern with the fetched dictionary URL as its base.
`select_dictionary_for_url` uses the outgoing request URL as the matching base, as specified by RFC 9842 Section 2.2.2, after origin,
partition, freshness and destination checks.
The existing origin/path APIs retain their signatures.
Full URLs canonicalize credentials, host, default port, path, query and fragment; the original full dictionary URL is not retained or added to store accounting.
Host processing follows the bounded Unicode 16 profile documented in `docs/URL_HOST_CANONICALIZATION.md`.

Authored patterns are limited to 2,048 bytes and complete URL input/output to 10,240 bytes.
A derived escaped component is admitted before graph construction at 24,576 bytes and at most 16,384 automaton states.
Canonical component input and output have an 8,192-byte ceiling.
Parsing, construction and matching share the selection allowance of 8,388,608 work units; exhaustion returns `LimitExceeded`.
Ordinary tests retain the previous store admission ceilings and verify negative/zero work, maximum inherited paths and graph admission.

`test/fixtures/urlpattern-wpt.json` retains 136 pathname-only cases from WPT revision `0c1d19546fd4873bb9f4147f0bbf868e7b4f91b7`, independently checked with the pinned Node 26.8.2 executable.
Every case is discovered through the ordinary EUnit generator.
`scripts/urlpattern_reference.mjs` verifies the specification, WPT, Unicode 16.0, reference executable, formatter and license bytes before reproducing that fixture and the Unicode identifier tables.
The tables use bounded binary search over constant ranges.
The upstream notices are retained in `LICENSES/BSD-3-Clause.txt` and `LICENSES/Unicode-3.0.txt`.
The same generator retains 33 constructor cases in `test/fixtures/urlpattern-constructor-wpt.json`.

`scripts/urlpattern_full_reference.py` independently reproduces 517 complete pattern/base/candidate cases using both pinned Node 26.8.2 and Chromium 153.0.8010.36 executables.
`test/fixtures/urlpattern-full-independent.json` records their matching results and exact executable identities.
Its ordinary generator discovers all 517 cases; direct tests additionally cover the public dictionary URL context, cross-origin rejection, base escaping, unrelated IPv6 patterns, fixed-group merging and default-port normalization order.
These regressions detected actual failures before their corresponding fixes.

Reference implementations are not substituted for the pinned algorithms.
The retained hostname object controls identify three Chromium-only acceptances of an empty hostname before `/`, `?` or `#`; this implementation follows the specified empty-buffer rejection.
Query apostrophes use the special-query encoding set.
Opaque-path callbacks follow the pinned URL state transitions for `?` and `#`, despite Chromium preserving those characters in the observed component setter.
These discrepancies remain explicit.
The RFC 9842 URLPattern requirement is covered by the source-bound 270-case semantic matrix, the 517-case independent corpus, direct consumer tests, and recorded normative decisions.
The [dictionary requirement inventory](DICTIONARY_REQUIREMENTS.md) now maps the RFC's 26 mandatory clauses, its additional procedures, and 23 constructor and callback profile obligations.
The map distinguishes implemented primitives from conditional automatic-CDT behavior that no library-owned endpoint can enter.

`test/dictionary_capability_test.gleam` covers the explicit `DestinationCapability` API.
`SupportedDestination("")` denotes the real empty [Fetch request destination](https://fetch.spec.whatwg.org/#requestdestination),
while `DestinationsUnsupported` causes matching and selection precedence to treat every stored destination list as empty.
The existing string-based `select_dictionary` retains its supported-destination semantics.
The added tests also fixed rejection of the valid `match-dest=("")` directive.
Origin,
partition, freshness, longest matching path, and recency remain enforced.

Explicit `clear_dictionaries` scopes remove one isolation partition, every partition belonging to an exact profile, or all dictionaries.
Tests compare the returned immutable store to an independently constructed surviving store,
including entry order, retained byte accounting and unchanged admission ceilings.
They cover repeated clearing, unknown scopes, invalid keys, other sites/profiles and multiple origins in a partition.
Scoped clearing makes one bounded traversal; clearing all immediately drops the returned value's list.
The caller must replace its authoritative store and discard older store and dictionary values.
The client's cookie store is a separate resource closed by `client.close`; `http.Client` neither owns this Store nor advertises a dictionary.
RFC 9842 Section 10 is therefore NotApplicable to library-owned client state.
An application that composes CDT must connect these explicit clearing scopes to its cookie policy.

The independent vectors are retained in `test/fixtures/brotli-google-synthetic.json`.
`scripts/brotli_reference.py` pins the upstream revision, checks the RFC dictionary bytes and transforms,
and regenerates the vectors.
The upstream MIT notice is retained in `LICENSES/LicenseRef-Brotli-MIT.txt`.
A separate diagnostic corpus of 420 independent decoder outputs was useful during implementation; it is not substituted for the ordinarily discovered retained tests in the requirement map.

The [RFC 7932 errata search](https://errata.rfc-editor.org/search/?rfc_number=7932) contained two entries at review: 5948 is a verified spelling correction;
6977 remains reported and clarifies that an implicit distance-zero command does not advance the distance-block count.
The implementation follows Section 10 and the independent no-distance-value ring-buffer vectors.
The RFC 9841 and RFC 9842 all-status searches returned no errata at review.

The public compression API operates on one explicitly supplied byte sequence.
Applications still control data provenance and must consider the compression side channel described in RFC 7932 Section 12: sensitive and attacker-controlled bytes should not share a compressed stream.
Raw prefix dictionaries are also content and require the same confidentiality and integrity treatment.
A hash match alone does not establish response readability, cross-origin policy, or permission to advertise a dictionary.

The RFC 7932 Section 11.3 independent-part construction is inapplicable to the current complete-stream encoder API.
Its mutable output-buffer fallback advice is likewise not a claim that the immutable BEAM encoder implements a second compressor: the encoder directly uses bounded stored blocks.
