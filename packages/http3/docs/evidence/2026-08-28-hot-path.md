# 2026-08-28 HTTP/3 hot path

- Date: 2026-08-28
- Baseline: `48a8b3b0a609b7c33ff54c571c9c5935ad41336f`
- Candidate: the baseline plus the tracked hot-path worktree patch described
  below
- Gleam: 1.18.1
- Erlang/OTP: 29 (erts 17.0.5), 8 online schedulers
- mise: 2026.8.14
- Host: Linux 6.8.0-138-generic x86_64, Intel(R) Core(TM) i7-7700K CPU @
  4.20GHz, 4 cores / 8 logical CPUs, 16,703,746,048 bytes memory

The candidate changes only internal implementation and tests:

- `quic_core` tracks streams with sendable output in an active round-robin
  queue plus a membership set instead of scanning every open stream;
- complete response bodies at or below 65,536 bytes use one server-worker
  command for HEADERS, DATA, and FIN, with the existing streaming path retained
  for larger bodies and send-buffer pressure; and
- direct tests cover stream activation, loss, credit recovery, reset, finish,
  fairness, complete-response boundaries, and atomic pressure fallback.

## Paired A/B

The baseline came from a `git archive` of `48a8b3b`; both trees used the same
pinned toolchain and prebuilt dependencies. Each retained pair ran adjacent
custom one-trial invocations, including an independent warm-up, and pair order
alternated. Raw rows are in
[`2026-08-28-hot-path-ab.csv`](../../benchmarks/results/2026-08-28-hot-path-ab.csv),
and each start's load average, CPU pressure, and frequency are in
[`2026-08-28-hot-path-environment.txt`](../../benchmarks/results/2026-08-28-hot-path-environment.txt).

| Mode | Candidate rps by pair | Baseline rps by pair | Candidate wins | Median change |
| --- | --- | --- | ---: | ---: |
| `benchmark` | 589, 659, 664, 625, 527 | 481, 544, 497, 523, 438 | 5/5 | 625 vs 497, +25.8% |
| `load` | 506, 533, 509, 485, 517 | 349, 343, 344, 339, 349 | 5/5 | 509 vs 344, +48.0% |

One exploratory candidate load invocation completed its warm-up, then timed
out during a host CPU-pressure burst without emitting a measured row. It was
excluded before the five retained pairs; the immediate baseline and candidate
retry both passed. No retained A/B row timed out or reported peer-close, every
row converged from 48 processes to 46, and every final mailbox count was zero.
