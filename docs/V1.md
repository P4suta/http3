# Pre-release v1 gate

The former “v1 complete” decision is reopened as of 2026-08-25. This source
tree contains a substantial live QUIC/HTTP/3 implementation, but it is not a
release candidate and must not be described as production-ready.

No tag, metadata-version change, hosted release, Hex upload, repository
creation, or push is authorized by this gate.

## Local development gate

The normal pull-request gate is:

```sh
mise run check
```

It checks both packages for formatting, warnings-as-errors builds, tests,
documentation, compiler-derived public API boundaries and semantic snapshots,
source/prose/configuration lint, workflow syntax, spelling, FFI
Dialyzer/xref, local Semgrep rules, gitleaks, REUSE data, and a twice-exported,
content-audited, byte-reproducible core Hex archive. Run `mise run security`
for the networked OSV lookup and CycloneDX artifact. Fault, generated,
interoperability, and performance tasks remain separate and must be run when
affected.

Passing this command means the current edit is internally consistent. It does
not close the open release findings.

## Release-candidate rule

A release candidate exists only after all of the following are true:

1. Every non-excluded conformance row is `Ready` and every `PRE-*` finding is
   closed with a directly linked test or gate.
2. The complete local, security, coverage, generated, fault, four-peer
   interoperability, package-simulation, platform, and performance gates pass
   from a clean source archive.
3. Benchmark, load, and soak reach at least 516, 344, and 812 requests/second
   on the recorded comparison host while idle polling remains zero and
   process/mailbox/memory cleanup stays within bounds.
4. Documentation and evidence carry the rerun date, both canonical API
   snapshots are intentionally approved, and no test key, cache, peer binary,
   qlog, pcap, or secret is present in either package archive.
5. A signed local commit is created only after the worktree is clean.

Even then, publication, tags, version changes, GitHub operations, Hex uploads,
and pushes require separate explicit authorization. An independent third-party
audit bundle is required, but completion of an external audit is recommended
rather than a source-tree gate. The unpublished/unaudited warning remains
until an audit actually finishes.

## Stable scope

The stable baseline is published QUIC v1/v2, TLS 1.3, HTTP/3, QPACK,
priorities, Extended CONNECT, Capsules, and Datagrams. qlog alone is pinned as
a non-negotiated diagnostic draft format.

HTTP/1.1, HTTP/2, fallback policy, Alt-Svc/SVCB policy, redirects, cookies,
caches, proxies, pooling, WebTransport, MASQUE, WebSocket framing, multipath,
ACK Frequency, reliable reset, extended key update, and the JavaScript target
remain outside v1.

The supported platform claim is Erlang/OTP 28 and 29 only, subject to the
release matrix. See [Support](../SUPPORT.md), [Testing](TESTING.md), and the
[security review](SECURITY_REVIEW.md).
