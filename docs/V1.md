# Public v1 completion gate

This document is the implementation and quality contract for the first public
release. It is not a version-number, tag, hosting, or package-publication
milestone. As of 2026-08-24, every source-tree implementation requirement and
every locally executable qualification gate is complete.

The only production QUIC implementation is the repository-owned
`packages/gleam_quic` package. The independent aioquic and quic-go stacks are
used only by the interoperability runner and do not appear in the production
dependency graph.

## Standards baseline

The stable baseline is the published IETF standards available on 2026-08-24.
Implemented behavior consumes the applicable verified errata. “Complete”
means that the feature is integrated into the live UDP client/server path,
bounded, negatively tested, and covered by standards vectors or independent
interop where applicable; it does not mean that one happy-path peer accepted
a request.

| Layer | Required specifications and behavior | Status |
| --- | --- | --- |
| QUIC invariants and versions | [RFC 8999](https://www.rfc-editor.org/info/rfc8999), QUIC v1 [RFC 9000](https://www.rfc-editor.org/info/rfc9000), QUIC v2 [RFC 9369](https://www.rfc-editor.org/info/rfc9369), and authenticated compatible version negotiation [RFC 9368](https://www.rfc-editor.org/info/rfc9368) | Complete |
| QUIC security | TLS 1.3 [RFC 8446](https://www.rfc-editor.org/info/rfc8446), QUIC-TLS and packet protection [RFC 9001](https://www.rfc-editor.org/info/rfc9001), certificate paths [RFC 5280](https://www.rfc-editor.org/info/rfc5280), and service identity [RFC 9525](https://www.rfc-editor.org/info/rfc9525) | Complete |
| Recovery and paths | ACK/loss/PTO, anti-amplification, Retry, address tokens, stateless reset, connection-ID rotation, NAT rebinding, migration, key update, ECN, IPv4, and IPv6 from RFC 9000 and [RFC 9002](https://www.rfc-editor.org/info/rfc9002) | Complete |
| Congestion and MTU | NewReno, CUBIC [RFC 9438](https://www.rfc-editor.org/info/rfc9438), UDP safety [RFC 8085](https://www.rfc-editor.org/info/rfc8085), pacing, and DPLPMTUD [RFC 8899](https://www.rfc-editor.org/info/rfc8899) without IP fragmentation | Complete |
| QUIC extensions | QUIC DATAGRAM [RFC 9221](https://www.rfc-editor.org/info/rfc9221) and QUIC-bit greasing [RFC 9287](https://www.rfc-editor.org/info/rfc9287) | Complete |
| HTTP/3 | Client/server semantics, control and request streams, SETTINGS, informational/final responses, DATA, trailers, push, GOAWAY, and graceful drain from [RFC 9114](https://www.rfc-editor.org/info/rfc9114) | Complete |
| QPACK | Static and dynamic tables, encoder/decoder streams, blocked-stream limits, feedback, and Huffman coding from [RFC 9204](https://www.rfc-editor.org/info/rfc9204) | Complete |
| HTTP extensions | Extensible priorities [RFC 9218](https://www.rfc-editor.org/info/rfc9218), Extended CONNECT [RFC 9220](https://www.rfc-editor.org/info/rfc9220), and correctly associated HTTP Datagrams and bounded Capsules [RFC 9297](https://www.rfc-editor.org/info/rfc9297) | Complete |

HTTP Datagram is not exposed as an unreliable side channel for an ordinary
GET or POST. Public sends require a negotiated Extended CONNECT association,
and the independent fixture verifies that association on the wire.

## Required product behavior

The v1 surface provides all of the following without exporting PIDs, atoms,
maps, references, socket records, cryptographic key material, or mailbox
formats:

- bounded buffered and backpressured streaming clients and servers;
- reusable connections, concurrent streams, typed cancellation and failures,
  total deadlines, keepalive, graceful draining, and deterministic cleanup;
- secure client defaults, SNI and hostname/IP verification, explicit trust
  stores, SNI certificate selection, session resumption, replay-constrained
  0-RTT, and automatic key update;
- QUIC v1 and v2, downgrade-safe negotiation, IPv4 and IPv6, path validation,
  NAT rebinding, active migration, ECN, PMTU discovery, NewReno, and CUBIC;
- complete QPACK, trailers in both directions, informational responses, server
  push, GOAWAY, Extended CONNECT, Capsules, HTTP Datagrams, and priority;
- explicit bounds for peer-controlled lengths, counts, queues, streams,
  tables, timeouts, retained state, and amplification; and
- opt-in qlog, path and connection statistics, repeatable benchmarks, and
  diagnostic errors that do not include secrets.

The compiler-exported interface is audited during every `mise run check`.
The opaque ticket API deliberately has no serialization or field accessor.
The public client deliberately has no certificate-verification bypass.

## Draft protocol policy

Internet-Drafts are not stable v1 requirements. This includes WebTransport
over HTTP/3, QUIC multipath, ACK Frequency, reliable stream reset, extended
key update, receive timestamps, and the evolving qlog event schemas.

Draft support must live in a clearly named experimental package pinned to an
exact draft revision. A changed or expired draft cannot silently alter or
block the standards-based core. Extended CONNECT, Capsules, HTTP Datagrams,
and generic QUIC streams provide the substrate for separate WebTransport,
MASQUE, or WebSocket packages; their application semantics do not belong in
this stable core.

## Implementation boundary

Protocol codecs, TLS transcript coordination, QUIC transport and stream state,
recovery, congestion control, scheduling, HTTP/3, and QPACK are Gleam code in
`packages/gleam_quic`.

Erlang FFI is restricted to runtime capabilities:

- UDP socket operations, address conversion, ECN ancillary data, and monotonic
  time;
- cryptographically secure randomness, hashes, HMAC, X25519, AEAD, and header
  protection;
- PEM/X.509/key decoding, certificate-path and service-identity validation,
  signatures, and constant-time comparison; and
- unique qlog file creation and diagnostic JSON output.

No FFI function parses or constructs a QUIC, TLS, HTTP/3, or QPACK wire
message or owns a protocol state machine. The root package's four-function FFI
only wraps existing opaque Gleam handles for the public transport facade.

The 2026-08-24 qualification uses pinned tool versions from `.mise.toml` and
the reproducible commands in [Testing](TESTING.md).

| Parser fuzz corpus | `mise run fuzz` passes 10,000 generated cases plus 16 retained regression seeds |

| Independent peers | `mise run interop` passes client and server directions against aioquic 1.3.0 and quic-go 0.61.0, including explicit QUIC v1/v2, authenticated RFC 9368 negotiation, Datagram, migration, qlog, resumption, and observed 0-RTT |

| Public boundary and repository quality | Compiler API audit, warnings-as-errors builds, docs, linters, shell checks, workflow validation, spelling, and REUSE checks pass |

The standards-conformance evidence is the native RFC vector, state-model,
negative, property, fuzz, and real-UDP corpus together with two independent
peers. It does not reuse or inherit a former backend's test count and does not
claim that an unavailable monolithic “official HTTP/3 certification suite”
exists.

## Platform gate

The supported range is Erlang/OTP 28 and 29, matching
[`Gleam 1.18`'s supported Erlang range][gleam-compatibility]. The checked-in
CI definition runs build and test jobs for both OTP releases and smoke jobs on
Linux, macOS, and Windows. Workflow syntax and pinned action revisions are part
of the local check. The retained qualification includes the full Linux/OTP 29
gate and clean root/native builds and all 386 tests in an official OTP 28
container. Hosted macOS and Windows results must be observed before a
publication action, once a hosted repository exists. Creating that repository
or triggering a release remains outside this source-tree gate.

## Completion rule

A later protocol change reopens every applicable gate. It must begin with a
failing regression or behavior test, pass `mise run check`, and rerun the
affected fault, fuzz, property, interop, or performance task. Publication,
tags, releases, version changes, and Hex operations always require a separate
explicit decision.

[gleam-compatibility]: https://gleam.run/documentation/compatibility-reference/
