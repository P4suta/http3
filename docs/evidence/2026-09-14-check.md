## The one blocking failure

`core-package` and the root `package` task both call `gleam export
hex-tarball`, which cannot succeed on Windows with Gleam 1.18.1:

    error: Cannot add path to tar archive

    The path
    \?\C:\...\packages\gleam_quic\src\gleam_quic\client.gleam is outside
    this Gleam project, so we cannot safely add it to the archive for
    publishing.

The file is inside the project. The check compares a file path that has been
canonicalised into a `\?\` extended-length path against a project root that
has not, so containment never holds. Three observations fix this as an
upstream toolchain bug rather than anything about this repository:

- both packages fail identically, at the first source file each;
- a `gleam new` project with no relation to this repository, at a 153-character
  path, fails with the same message; and
- no component of either path is a junction, symlink, or other reparse point,
  and both are far below `MAX_PATH`.

Nothing in this repository can work around it, and CI is unaffected. It blocks
a Windows developer from running `mise run check` end to end, nothing more.

## Two Windows defects fixed to reach that state

Both were real portability bugs in this repository, not environment problems.

`.mise.toml`: the `semgrep` and `sbom` tasks begin with `mkdir -p` and, for
semgrep, a POSIX inline environment assignment. mise runs task commands through
`cmd.exe` on Windows, which answers `The syntax of the command is incorrect.`
Both tasks now declare `shell = "bash -c"`. The check gate already requires
bash for `bash test/run_ffi_audit.sh` and lints four shell scripts with
shellcheck and shfmt, so this adds no new requirement on any platform.

`test/run_mix_gleam_package.sh`: the gate's real work succeeded and the script
still exited 1. Its `cleanup` trap ran `find "$build_directory" -depth -delete`
while the working directory was inside that tree, left there by the `cd
"$stage"` the staged build needs. On msys `find` then fails with `Failed to
restore initial working directory`, and `set -eu` turns that into a failed
gate. The trap now leaves the tree before deleting it.
